ESTIMATING FLOW WITHOUT A FLOW SENSOR

Know how much water a pump moves from the power it draws.

A small ESP32 watches a pump's electrical power and turns it into a flow estimate. A weighed-water load cell is used only to calibrate and check that estimate, so the finished system needs no flow meter in the pipe.

HOW IT WORKS

From electrical power to a flow number

A pump that moves more water works harder and draws more power. The system learns that relationship once, using weighed water as the truth, and then reads flow from power alone.

    CONCEPTS AND THEORY

    The ideas behind the project

    Each card says what the idea is, how it is used here, and honestly where it stands: running on the hardware, running in simulation, or still planned.

    Virtual (soft) sensor

    ON HARDWARE

    Estimates a quantity you do not measure directly from quantities you do. Here, flow comes from the pump's electrical power, so there is no flow meter in the pipe to clog, restrict or fail.

    gateway/estimator.py · vfm_estimator.h

    Reference-based calibration

    TOOLS BUILT

    Water is caught in a jug on a load cell. Flow is the mass gained over time, divided by density. Those weighed values are the ground truth that the power model is fitted to and judged against.

    tools/calibrate_loadcell.py · record_collection.py · fit_power_model.py

    Edge computing

    BUILT, FLASH PENDING

    The ESP32 computes the estimate itself from a 10 Hz loop and sends a one-per-second summary. It keeps estimating without the laptop and sends far less data. See the Edge computing section.

    device/firmware/vfm_edge/

    Honest uncertainty

    ON HARDWARE

    A model is only valid where it was calibrated. Outside its ranges, or where power barely changes with flow, the system says "Unavailable". Results are checked on runs the model never saw, and profiles carry a checksum.

    profile checks · held-out validation

    Online learning

    SIMULATION

    Recursive least squares keeps adjusting the model as data arrives. A CUSUM detector flags drift, and an excitation gate refuses to learn unless the flow varied enough to teach anything.

    vfm/slowloop.py

    Machine unlearning

    SIMULATION

    If a bad run (a leak, an air pocket) has taught the model something wrong, its influence is removed directly with a Sherman–Morrison downdate, instead of retraining from scratch.

    vfm/slowloop.py · LearningModule.downdate

    Digital triplet

    SIMULATION

    A supervisor runs the system in Manual, Assisted or Auto mode, requires operator approval for model changes, and trips safely on faults. The physical device, its model and the operator stay in the loop together.

    vfm/supervisor.py

    Sensor fusion

    PLANNED

    Discharge pressure would be a second, independent input, so power and pressure can cross-check each other. No suitable pressure sensor is fitted yet, so pressure is not used.

    needs a water-compatible pressure sensor

    REFERENCE FLOW

    Qref = 60 · Δm / ( ρ · Δt )

    Δm is kilograms gained, Δt seconds, ρ the water density in kg/L. The 60 converts litres per second to litres per minute.

    POWER MODEL

    P(Q) = c0 + c1Q + c2Q²

    Fitted from the weighed runs. Flow is recovered by solving this for Q on the branch where power rises with flow.

    DRIFT DETECTION

    St = max( 0, St−1 + zt − k )

    CUSUM accumulates small persistent errors and raises an alarm when the sum crosses a threshold.

    UNLEARNING

    (A + uvT)−1 = A−1 − A−1uvTA−1 / (1 + vTA−1u)

    A rank-one update of a matrix inverse, so one sample's influence is removed without a full refit.

    WHY EDGE

    • Local decisions. The estimate and its checks run on the device, not on a server.
    • Less data. Ten samples per second are reduced to one summary per second, about a tenth of the readings sent.
    • Resilience. If the laptop or link drops, the device keeps estimating.
    • Predictable latency. The compute time and loop time are measured on the device and shown here.

    ABOUT THE PROJECT

    Self-Calibrating Virtual Flow Meter

    A low-cost way to read a pump's flow from its power, calibrated against weighed water, with the estimate computed on the device. It is a bench prototype for one pump on one rig.

    THE PUMP

    ModelAD-03 submersible
    Rating (label)12 V DC, 20 W
    Max head / max flow6.0 m / 15 L/min
    ProtectionIPX8

    The label maxima are separate end points, not a measured operating point.

    HARDWARE

    • ESP32 controller and edge processor
    • INA219 pump voltage, current and power
    • DS18B20 water temperature, for density
    • 5 kg load cell + HX711 weighed reference
    • LM2596 + servo valve actuation

    SOFTWARE

    • Firmware Arduino C++ on the ESP32
    • Gateway Python, HTTP, checksummed profiles
    • Tools calibration, collection, model fitting
    • Dashboard plain HTML, CSS and JavaScript
    • Simulation learning, unlearning, supervisor

    WHAT IS AND IS NOT CLAIMED

    No flow model is loaded, so no flow estimate is shown. Learning, unlearning and the supervisor run in simulation only.
